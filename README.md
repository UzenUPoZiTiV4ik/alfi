## что делает

финдир крупной компании тонет в новостях: большинство не про его бизнес, а в остальных непонятно, что делать.

- собирает **16 rss-лент** (включая цб, прайм, forbes, интерфакс, рбк, ведомости, коммерсантъ) и ищет через exa; чистит utm в ссылках, проверяет даты, склеивает перепечатки в события в окне 48 часов
- строит профиль компании из данных банка: отрасль, узкий оквэд, вэд, кредиты, контрагенты, группа (строго разделяя компанию клиента, контрагентов и группу)
- оставляет в ленте только значимые события для этого бизнеса, отсекает чужие отрасли, лайфстайл и биржевые дайджесты, и объясняет почему новость в ленте
- пишет разбор: факты, влияние по сферам, риски, возможности **с условиями реализации**, сценарии, шаги; не переносит общий рост рынка на компанию
- явно отделяет подтверждённые факты, **позицию альфа-банка** (строго из `bank:*` с датой отчёта) и **выводы ии** (с дисклеймером); при оставшихся противоречиях или неподтверждённых цифрах не выдаёт разбор как готовый, а помечает **«требует проверки»**
- привязывает историю чата к конкретному событию, сохраняет сноски и учитывает уточнения пользователя (`user:*`) с высшим приоритетом

## запуск

для генерации нужен `LLM_API_KEY`, для веб-поиска через exa нужен `EXA_API_KEY`. учебная лента работает без ключей.

```bash
cp .env.example .env      # вписать ключи и SESSION_SECRET
docker compose up --build
```

открыть http://localhost:8000, swagger на `/docs`.

без docker:

```bash
cd server
export ALFI_DEMO_MODE=1
uv sync --locked
uv run python -m scripts.bootstrap
uv run uvicorn app.main:app --port 8000
```

### быстрое демо без csv

из `server/` создай синтетическую базу с двумя компаниями, новостями и банковским тезисом. при входе выбери компанию из списка.

```bash
uv run python -m scripts.seed_demo --db /tmp/alfi-demo.db
ALFI_DEMO_MODE=1 DB_PATH=/tmp/alfi-demo.db INGEST_INTERVAL_MIN=0 uv run uvicorn app.main:app --port 8000
```

## данные

данных кейса в репозитории нет, положите свои:

```
server/data/raw/df_Uid_data_hack.csv
server/data/raw/df_Uid_payment_hack.csv
server/data/raw/df_Fid_Uid_link_hack.csv
server/data/kb/pdf/*.pdf
```

`scripts/bootstrap.py` при старте соберёт базу из csv (около 10 секунд) и базу знаний из pdf. в докере ocr идёт через qwen3-vl: до часа и примерно 20 ₽. на маке через apple vision - пара минут и бесплатно.

без данных сервис тоже стартует: работает режим «описать свой бизнес».

## проверка

1. открыть `/`, выбрать `U_34911` (зерно, 53,9 млрд ₽, вэд в оаэ, алжир, индию) и роль «финансовый директор»
2. в ленте риски и возможности именно для зернотрейдера, под карточкой сферы, шаг и позиция банка
3. нажать на сферу в «где это бьёт по бизнесу» - лента отфильтруется
4. «открыть разбор»: видно шаги агента, сверху дисклеймер (и баннер «требует проверки», если остались спорные места), раздельные блоки фактов, позиции альфа-банка и выводов ии, условия у возможностей и все найденные источники с URL
5. в разборе добавить уточнение в блок «Уточнить контекст вашей компании» или написать факт в чате «спросить про разбор» - история привяжется к этой новости, сноски сохранятся, а уточнение `user:*` попадёт в пересборку
6. сменить роль на бухгалтера в меню аккаунта: лента и команда пересоберутся
7. «сменить бизнес» → «описать свой бизнес»: лента под новую компанию
8. «проверить свою новость»: вставить текст и получить разбор
9. служебный `GET /api/metrics` с заголовком `X-Admin-Token`: качество, `ready_rate` и расходы за день

## как устроено

![архитектура](docs/diagrams/01-architecture.png)

fastapi и sqlite в одном сервисе, фронтенд без сборки. слои разделены (`main.py` только http/sse, `ingest.py` сбор, `feedback.py` отклик, `dates.py` даты, `db.py` sql). агент написан руками, каждый шаг пишется в журнал и уходит в браузер через sse.

<details>
<summary>откуда ии берёт факты</summary>

![источники](docs/diagrams/02-agent-sources.png)

у каждой находки свой id и URL: `feat:*` факт о компании, `data:*` платежи и группа (с явным разделением юрлиц), `news:*` новость, `bank:*` тезис банка с датой, `web:*` страница, `user:*` уточнение пользователя с высшим приоритетом. выдуманные ссылки вычищаются, а все найденные дополнительные источники сохраняются в карточке разбора.
</details>

<details>
<summary>сбор новостей</summary>

![сбор](docs/diagrams/03-news-ingest.png)

вынесен в `ingest.py`, запускается раз в час и по кнопке. 16 rss-лент (+ прайм, forbes) и exa (`search` type=auto и `contents` с кэшем). URL очищается от utm-меток, даты проверяются `dates.py`, перепечатки склеиваются в кластер ≤ 48 ч с защитой от конфликта цифр и выбором самого полного источника. при изменении текста по `content_hash` транзакционно обновляются теги и сбрасываются `triage` и `insights`.
</details>

<details>
<summary>почему новость в ленте</summary>

![лента](docs/diagrams/04-personal-feed.png)

```
score = base × значимость × тип × масштаб × свежесть × доверие × кластер × отклик
base  = 0,62·отрасль + 0,58·фактор + оквэд + гео
```

порог 0,16, не больше 4 событий на фактор. чужие отраслевые события (×0,25 / ×0,20), лайфстайл (×0,30), биржевые сводки (×0,52) и ретро-годы (×0,78) штрафуются. отклик «полезно / не про нас» меняет веса в `feedback.py`.
</details>

<details>
<summary>разбор</summary>

![разбор](docs/diagrams/05-insight-agent.png)

10–11 правил верификации (добавлены `opportunity_conditions` и `user_clarifications_used`), затем 6-осевой кросс-критик другой моделью (`+ source_fidelity`, `+ no_overclaim`, проверка противоречий). после точечной доработки критик перепроверяет разбор. если остались неподтверждённые цифры или противоречия - срабатывает честный гейт `needs_review` (уверенность ≤ 55%, баннер «требует проверки»).
</details>

> **почему именно эта связка:** `deepseek-v4.1-flash (off)` даёт лучшую комбинацию скорости (51,6 с), цены (0,86 ₽, ~698 разборов/день), глубины цитирования (10,2 сноски и 25+ сохранённых источников) и оценки критика (0,927). `selective low` поднимает точность цифр до 100% за 98,5 с и 1,20 ₽, а `selective high` даёт 0,930 и 12,8 сносок за 115,6 с / 1,39 ₽ - в проде оставлен быстрый `off`, а при необходимости `low`/`high` включается одной переменной окружения. `glm-5.3-flash (off)` идеальна как независимый критик (0% галлюцинаций на `off`/`medium`/`high`, 0,044 ₽), но как генератор длинного разбора в 2–3× медленнее. `kimi-k2.6` в 5,7× дороже и проигрывает по цифрам.

### 3. качество ранжирования ленты (ДО vs ПОСЛЕ)

эталон из **80 размеченных пар** (5 компаний разных отраслей × 16 разнородных новостей, оценка 0..3) при реальном пороге ленты `0,16`:

| метрика | до (отборочная версия) | после (финал) | изменение |
|---|---:|---:|---:|
| **Precision@5** (доля важных `rel ≥ 2` в топ-5) | 76,0% | **92,0%** | **+16,0 п.п.** |
| **FeedNoise ↓** (доля шума `rel = 0` во всей выданной ленте) | 54,0% | **3,3%** | **-50,7 п.п.** |
| **Noise@5 ↓** (доля шума в топ-5) | 4,0% | **0,0%** | **-4,0 п.п.** |
| **NDCG@5** | 0,955 | **0,970** | **+0,015** |
| **NDCG@10** | 0,947 | **0,952** | **+0,005** |
| **Diversity@5** (различие топ-5 между компаниями) | 0,710 | **0,736** | **+0,025** |
| **HitRate@3 / MRR** | 1,000 / 1,000 | **1,000 / 1,000** | 0,000 |

![замер ранжирования](docs/diagrams/10-bench-ranking.png)

повторить все 3 замера (сырые данные сохранены в `docs/bench/`):

```bash
cd server
.venv/bin/python -m scripts.bench_ranking --out ../docs/bench/ranking.json
LLM_API_KEY=... .venv/bin/python -m scripts.bench_faith --out ../docs/bench/faithbench.json
LLM_API_KEY=... .venv/bin/python -m scripts.bench --out ../docs/bench/results.json
```

> **методическая оговорка:** все цифры выше - реальные измерения на зафиксированных эталонах (`docs/bench/ranking.json`, `faithbench.json`, `results.json`). кросс-критик у `deepseek` (`glm-5.3-flash`) и у остальных моделей (`deepseek-v4.1-flash`) имеет разную калибровку строгости, поэтому при выборе моделей мы опирались на совокупность детерминистических правил (10–11 правил + цифры), `Alfi-FaithBench` с независимым судьёй, латентности и стоимости. бизнес-эффект в проде (экономия времени финдира) - гипотеза и в замерах не приписывается как измеренный факт.

### методика разметки, edge-кейсы и ограничения измерений

- **разметка эталона ранжирования (`bench_cases.py`):** 5 профилей из разных отраслей (зерно/ВЭД, напитки, топливо, стройка, автологистика) × 16 разнородных новостей = 80 пар. разметка экспертная по 4-балльной шкале: `0` шум или чужая отрасль, `1` косвенная связь / ретро-статистика, `2` значимое макрособытие (ставка ЦБ, налоги), `3` прямое критичное событие для отрасли/ОКВЭД компании.
- **разметка `Alfi-FaithBench`:** 6 категорий × 3 кейса-ловушки с жёстко заданным `allowed_numbers`, флагом наличия `bank:*` и эталонным правилом `trap_rule`, по которому проверяет независимый cross-family судья.
- **проверенные edge-кейсы (автотесты `tests/test_core.py`, `tests/test_final_fixes.py` + E2E):** неполные данные без платежей и группы (`E2E_DEMO`, `abs_01`), противоречивые прогнозы банка по датам (`fi-3q26` 14,25% vs `rate-11sep` 14,0%), устаревший PDF 2021 года (`[устаревший]`), битые и будущие даты (`2099`, `2026-10`), обновление текста новости с каскадным сбросом кэша, пустой `why_it_matters` и JSON-массив от модели, попытка prompt-injection, маскировка ПД, RBAC по ролям, отказ LLM-шлюза (переключение на `demo_insight` и запасную модель без reasoning).
- **ограничения замеров:** выборки эталонные и синтетические, а не полевое A/B-тестирование с действующими финдиректорами; для оценки реального CTR и Time-to-Insight нужен ограниченный пилот.

## эксплуатация и масштабирование

### поддержка актуальности после пилота

- **новые отрасли, факторы и продукты:** вынесены в декларативные словари в `server/app/taxonomy.py` и правила маппинга признаков в `server/app/profile.py`. добавление новой отрасли или продукта не меняет код агента и ленты - достаточно обновить словарь, пересобрать кэш профилей и прогнать регрессию.
- **контроль качества, версионирование и откат:** промпты, веса формулы и словари хранятся в git; перед выкаткой прогоняются `pytest -W error`, `bench_ranking.py` (порог деградации по Precision@5 и FeedNoise) и `bench_faith.py` (порог по галлюцинациям). в рантайме режим мышления и модели переключаются через переменные окружения (`MODEL_*`, `LLM_REASONING*`) без пересборки образа; кэш разборов автоматически сбрасывается при изменении текста новости (`content_hash`) или уточнений (`clarification_hash`).
- **динамика профилей в проде:** на датасете кейса доступен один временной срез, поэтому пересчёт профилей при смене структуры группы, ВЭД или кредитного портфеля заложен на уровне контракта - регулярный инкрементальный пересчёт таблицы `companies`/`payments` с инвалидацией кэша `profile.invalidate_cache()`.

### реализовано в прототипе и проектные решения для прода

| контур | реализовано в прототипе | целевое решение в проде |
|---|---|---|
| доступ и аутентификация | HttpOnly cookie + HMAC-подпись сессий, RBAC инструментов по ролям (`security.py`) | корпоративный SSO Альфа-Бизнеса, привязка к ролям ЕСИА/ДБО, закрытие демо-ручек |
| защита данных и аудит | маскировка ИНН/телефонов/счетов, рамка «данные, не инструкции», детектор инъекций, таблицы `tool_audit` и `llm_calls` | централизованный SIEM, DLP-фильтр на шлюзе, ротация и архивация журналов |
| сбор и хранилище | SQLite WAL, `ingest.py` с планировщиком в процессе, лексический BM25 в памяти | PostgreSQL + pgvector/FTS, выделенный воркер `ingest` и очередь разборов (Redis/Celery) |
| отказоустойчивость | повторы с backoff, запасная модель (`qwen3.6-35b` строго `off`), кэш разборов и Exa, резервирование дневного бюджета, деградация в `demo_insight` | балансировка между несколькими LLM-пулами, circuit breaker и алертинг по p95 и доле `needs_review` |

### ограничения масштабирования и экономика

- **производительность прототипа:** лента отдаётся за <100 мс (плюс `ETag`/`304`), полный разбор события занимает **51,6 с** (`deepseek-v4.1-flash off`) или **77,9 с** (`selective low`).
- **стоимость эксплуатации:** один глубокий разбор стоит **0,86 ₽** (или **1,14 ₽** в `selective low`), разметка одной новости - **0,018 ₽** (`gemma-4-26b`). в бюджете **600 ₽/сутки** помещается **~698 разборов** или **~32 500 разметок**; дневные пороги `BUDGET_SOFT_RUB` / `BUDGET_HARD_RUB` с транзакционным резервированием защищают от перерасхода.
- **узкие места при росте нагрузки:** запись в SQLite (`BEGIN IMMEDIATE`) упирается в ~20-30 одновременных пишущих запросов; BM25-индекс держится в RAM каждого воркера; квота Exa ограничена `EXA_DAILY_LIMIT=300` запросов/сутки (смягчается кэшем `exa_cache` и 16 RSS-лентами). при масштабировании на тысячи клиентов БД выносится в PostgreSQL, сбор новостей и генерация разборов - в отдельные фоновые воркеры, а частые макрособытия (ставка ЦБ, налоги) переиспользуют общий контекст и банковские тезисы.

## api

схема в [docs/api/openapi.json](docs/api/openapi.json), swagger на `/docs`. браузер получает HttpOnly cookie `alfi_session` при входе в компанию. для программного клиента подходит `Authorization: Bearer`. при включённом `SITE_PASSWORD` форма `/gate` выдаёт отдельную cookie `alfi_gate`. выход из компании очищает только `alfi_session`.

| путь | что делает |
|---|---|
| `POST /api/session` | вход: компания и роль |
| `GET /api/feed`, `/api/profile` | лента и профиль |
| `GET/PUT/DELETE /api/team` | команда помощников |
| `GET /api/insight/{id}/stream` | разбор события, SSE (`ready` / `needs_review`) |
| `GET /api/insight/{id}/clarifications` | список уточнений пользователя `user:*` по событию |
| `POST /api/insight/{id}/clarify` | добавить уточнение о компании и сбросить кэш разбора |
| `POST/GET/DELETE /api/chat` | чат с помощником (поддерживает привязку `news_id` и сохранённые `refs`) |
| `POST /api/news/submit`, `/api/feedback` | своя новость, отклик |
| `GET /api/kb/docs`, `/api/kb/pdf/{id}` | аналитика банка |
| `GET /api/metrics` | качество (`ready_rate`, 6 осей критика) и расходы |

лента поддерживает `ETag`: с `If-None-Match` сервер вернёт `304`, пока выдача та же. после обрыва SSE клиент продолжает поток по `run_id` с последнего события (`GET /api/runs/{run_id}/stream`). у помощников можно менять частоту и часовой пояс через `PUT /api/team/{member_id}/schedule`.

> в демо вход открытый: выбрать можно любую компанию кейса. в проде токен выдаёт SSO, а демо-ручки закрываются.
